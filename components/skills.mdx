The Skills page transforms a traditional skills list into an arcade control panel. Three `SkillCabinet` sections — each styled as a different arcade cabinet — group the developer's technical abilities by category. Within each cabinet, individual skills are displayed as large circular coin-op buttons. Hovering over a button reveals a tooltip showing the skill's numeric level out of 100 and a short description. All skill data is drawn from the `skills` array in `data/mockData.js`, organized into frontend, backend, and tooling categories, each with its own cabinet color theme.

| Property | Value |

| Path | `/skills` |

## What It Displays

The page renders three `SkillCabinet` sections stacked vertically. Each cabinet has a colored heading and contains a row of circular buttons — one per skill.

## Animations

Each `SkillCabinet` section uses Framer Motion's `whileInView` trigger with a `scale` animation. Buttons scale from `0.8` to `1.0` as they enter the viewport, staggered by `0.08 s` per item.

```js
// Approximate SkillCabinet button animation variant
const skillButtonVariants = {
  hidden: { opacity: 0, scale: 0.8 },
  visible: {
    opacity: 1,
    scale: 1,
    transition: { duration: 0.3, ease: "easeOut" },
  },
};

// Stagger applied at the container level
const cabinetVariants = {
  hidden: {},
  visible: {
    transition: { staggerChildren: 0.08 },
  },
};
```

<Note>
  The `whileInView` animation fires once per cabinet as it scrolls into view. The `once: true` viewport option prevents re-triggering on scroll back. Level tooltips are CSS-only and do not use Framer Motion.
</Note>

## Tooltip Behavior

Hovering over a skill button reveals a floating tooltip anchored above the button. The tooltip displays:

- **Skill name** — the same label shown on the button face
- **Level** — a numeric value from 0–100 (e.g. `LVL 99`)
- **Description** — a one-sentence note about proficiency or usage context

Tooltips are styled with `bg-arcade-black`, `border-arcade-lime`, and `font-mono` text to match the cabinet aesthetic. They appear via a CSS `opacity` + `translateY` transition on hover.

## Data Schema

Each entry in the `skills` array must conform to the following shape:

```ts
type Skill = {
  id: string;          // Unique identifier, used as React key
  name: string;        // Display label on the button face
  level: number;       // Proficiency level 0–100
  description: string; // Tooltip description line
  category: "frontend" | "backend" | "tooling"; // Cabinet assignment
};
```

### Field Reference

| Field | Type | Displayed As | Notes |
|---|---|---|---|
| `id` | `string` | Not displayed | Used as React list key |
| `name` | `string` | Button face label | Keep short — max ~12 chars |
| `level` | `number` | Tooltip `LVL <value>` | Integer 0–100 |
| `description` | `string` | Tooltip body text | One sentence recommended |
| `category` | `string` | Cabinet grouping | Must be one of three valid values |

## Customization

**Adding a new skill**

Append a new entry to the `skills` array in `data/mockData.js`. The `category` field controls which cabinet it appears in.

```js
// data/mockData.js
export const skills = [
  // ... existing entries
  {
    id: "astro",
    name: "Astro",
    level: 70,
    description: "Building content-driven sites with Astro's island architecture.",
    category: "frontend",
  },
];
```

**Changing a skill level**

Update the `level` field for the relevant skill entry. The level value affects only the tooltip display — there is no visual progress bar on the button face itself.

**Adding a new cabinet category**

The `SkillCabinet` component accepts a `color` prop. If you add a fourth category (e.g. `"design"`), you'll need to add a new `SkillCabinet` instance in `SkillsPage` and filter skills by the new category string.

```jsx
// Adding a fourth cabinet in SkillsPage
<SkillCabinet
  title="DESIGN"
  color="magenta"
  skills={skills.filter((s) => s.category === "design")}
/>
```

<Tip>
  Skill button labels render in `VT323` pixel font. Names longer than about 12 characters will wrap inside the circular button boundary. Keep skill names concise — abbreviate if needed (e.g. `TS` for TypeScript, `PG` for PostgreSQL).
</Tip>

## SkillCabinet Props

The `SkillCabinet` component used on this page accepts the following props:

| Prop | Type | Description |
|---|---|---|
| `title` | `string` | Cabinet section heading |
| `color` | `"lime" \| "purple" \| "cyan" \| "magenta"` | Accent color for cabinet border and heading glow |
| `skills` | `Skill[]` | Array of skill objects filtered to this cabinet |
